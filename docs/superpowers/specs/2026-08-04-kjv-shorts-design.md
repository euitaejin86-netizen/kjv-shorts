# 킹제임스 성경 묵상 쇼츠 반자동 제작 파이프라인 — 설계

작성일: 2026-08-04

## 1. 목적

킹제임스 흠정역 성경을 소재로 한 유튜브 쇼츠(1–3분 세로 영상)를 주 2–3개씩
반자동으로 제작한다. 대본 작성부터 MP4 렌더링까지는 사람 손을 타지 않고,
업로드 직전에만 사람이 확인한다.

## 2. 확정된 전제

| 항목 | 결정 |
|---|---|
| 포맷 | 말씀 묵상 쇼츠, 1–3분, 9:16 세로 |
| 구절 선정 | 주제 로테이션 (믿음 → 구원 → 은혜 → …) |
| 한글 본문 | 킹제임스 흠정역, '그리스도예수안에' 출판사 판 |
| 영어 본문 | KJV (퍼블릭 도메인) |
| 대본 생성 | Claude Code 자체 (별도 API 비용 없음) |
| 비주얼 | 정적 배경 이미지 + Ken Burns 줌 + 자막 |
| TTS | edge-tts (무료, API 키 불필요) |
| 렌더링 | FFmpeg |
| 분량 | 주 1회 배치, 2–3개 |
| 승인 지점 | 영상 생성까지 자동, 업로드 실행은 사람이 |

## 3. 원 요구사항 대비 범위 결정

원 요청의 7개 요구사항 중 4개만 구현한다.

| 원 요구사항 | 결정 | 근거 |
|---|---|---|
| 1. PDF 텍스트 추출 | 구현 | 모든 것의 전제 |
| 2. 주제별 태깅 | **삭제** | 실제 필요한 동작은 "이 주제 자료 어디 있나" 하나뿐이고 `grep`으로 충족된다. 태그 스키마·저장소·관리 비용만 남는다. |
| 3. 대본 생성 | 구현 (코드 0줄) | Claude Code가 직접 수행 |
| 4. TTS | 구현 | edge-tts |
| 5. 영상 렌더링 | 구현 | FFmpeg |
| 6. 썸네일 생성 | **삭제** | 쇼츠는 세로 피드에서 재생되어 썸네일 노출이 사실상 없다. 영상 첫 프레임이 그 역할을 한다. |
| 7. 업로드 | 구현 | YouTube Data API v3 |

추가로 **스케줄러(Windows 작업 스케줄러)도 만들지 않는다.** 주 2–3개 규모에서는
사람이 주 1회 Claude Code에 한 줄 입력하는 편이 빠르고, 그 시점에 주제·톤을
조정할 여지도 생긴다. 분량이 주 10개를 넘으면 그때 도입한다.

## 5. 아키텍처

### 5.1 디렉터리

```
kjv-shorts/
  bible/
    kjv_ko.json          # 파서 산출물 (1회 생성)
    kjv_en.json          # 영어 KJV, 퍼블릭 도메인 파일 다운로드
  corpus/
    *.txt                # 주석서 109개 → 텍스트 (1회 생성, grep 대상)
  bg/
    *.jpg                # 배경 이미지 (수동으로 몇 장 준비)
  topics.json            # 주제 로테이션 목록 + 다음 순번
  scripts/
    YYYY-MM-DD-<topic>-NN.json   # 대본 (Claude Code가 작성)
  out/
    YYYY-MM-DD-<topic>-NN.mp4    # 완성 영상

  parse_bible.py         # 1회: 본문 PDF → bible/kjv_ko.json
  extract_corpus.py      # 1회: 주석 PDF 109개 → corpus/*.txt
  build.py               # 매번: 대본 JSON → MP4
  upload.py              # 매번: MP4 → 유튜브 예약 업로드
```

새로 작성하는 파이썬 파일은 4개이고, 그중 2개는 최초 1회만 실행한다.
상태 관리는 "파일이 어느 폴더에 있는가"로 충분하다. DB도, 큐 폴더 체계도 두지 않는다.

### 5.2 모듈 경계

각 스크립트는 파일을 통해서만 소통한다. 서로를 import하지 않는다.

| 스크립트 | 입력 | 출력 | 의존 |
|---|---|---|---|
| `parse_bible.py` | 본문 PDF | `bible/kjv_ko.json` | PyMuPDF |
| `extract_corpus.py` | 주석 PDF 109개 | `corpus/*.txt` | PyMuPDF |
| `build.py` | 대본 JSON 1개 | `out/*.mp4` | edge-tts, FFmpeg |
| `upload.py` | MP4 1개 | 유튜브 예약 게시물 | google-api-python-client |

이 경계 덕분에 영상 스타일을 바꿔도 대본 형식은 그대로이고, 대본 톤을 바꿔도
렌더링 코드는 건드리지 않는다.

### 5.3 대본 JSON 스키마

Claude Code와 파이썬 코드 사이의 유일한 계약이다.

```json
{
  "topic": "믿음",
  "ref": "히브리서 11:1",
  "verse_ko": "이제 믿음은 바라는 것들의 실체요, 보이지 않는 것들의 증거니",
  "verse_en": "Now faith is the substance of things hoped for, the evidence of things not seen.",
  "narration": ["문장 1.", "문장 2.", "문장 3."],
  "bg": "bg/dawn.jpg"
}
```

- `narration`은 문장 단위 배열이다. 문장별로 TTS를 돌려 실제 오디오 길이를 재고,
  그 길이로 자막 타이밍을 정하기 때문이다. 통짜 문자열이면 타이밍을 추정해야 한다.
- `verse_ko` / `verse_en`은 `bible/*.json`에서 그대로 가져온 값이어야 한다.
  Claude Code가 기억에 의존해 성경 구절을 쓰지 않는다.

### 5.4 topics.json 형식

```json
{
  "next": 2,
  "topics": ["믿음", "구원", "은혜", "회개", "기도", "소망", "사랑"]
}
```

`next`는 다음에 사용할 주제의 인덱스다. Claude Code가 대본을 쓴 뒤 이 값을
갱신하며, 목록 끝에 도달하면 0으로 돌아간다. 주제 추가·삭제는 사용자가 이
파일을 직접 편집한다.

## 6. 주간 작업 흐름

1. 사용자가 Claude Code에 "이번 주 3개 만들어줘"라고 입력
2. Claude Code가 수행:
   - `topics.json`에서 다음 주제 확인
   - `corpus/`를 grep해 해당 주제의 교리적 근거 자료 참고
   - `bible/kjv_ko.json`, `bible/kjv_en.json`에서 구절 인용
   - `scripts/`에 대본 JSON 3개 작성, `topics.json`의 순번 갱신
3. `python build.py scripts/2026-08-11-*.json` → `out/`에 MP4 3개
4. 사용자가 영상 확인
   - 좋으면 `python upload.py out/xxx.mp4`
   - 아니면 파일 삭제 (또는 대본 수정 후 3번 재실행)

## 7. 성경 파서 설계 (이 프로젝트의 핵심 위험)

### 7.1 왜 어려운가

추출된 텍스트는 인쇄용 2단 조판 그대로다. 실제 페이지 24 추출 결과:

```
7                          ← 페이지 번호
창세기 6                    ← 러닝 헤더 (실제 내용은 창세기 5장)
9 ¶ 에노스는 구십 년을 살며 게난
을 낳았고                   ← 한 절이 여러 줄로 분리됨
...
셈의 세대들(대상1:17-27)     ← 편집자 소제목이 본문 사이에 삽입됨
```

### 7.2 조판 구조 (PyMuPDF 폰트·좌표 정보로 검증 완료)

문자열 휴리스틱 대신 **글자 크기와 x좌표로 요소를 판별한다.** 실측 결과:

| 요소 | 글자 크기 | x좌표 | 비고 |
|---|---|---|---|
| 절 시작 줄 | 12.1 | 46 (좌단) / 226 (우단) | 들여쓰기 있음 |
| 절 이어지는 줄 | 11.8 (일부 11.2) | 37 / 217 | 들여쓰기 없음 |
| 편집자 소제목 | 10.4 | 80 부근 | 가운데 정렬 |
| 페이지 번호·러닝 헤더 | 10.9 | y ≈ 19 | 페이지 최상단 |
| 권 소개 블록 | 10.2–10.4 | 42 | 각 권 시작 페이지에만 |

**절 시작을 판별하는 신호는 들여쓰기다.** 절 시작 줄은 본문보다 9pt 들여쓰기되어
있고 숫자로 시작한다. 소제목은 절대 숫자로 시작하지 않는다. 이 두 조건으로
소제목·본문·절 시작이 모두 구분된다.

2단 조판이며 좌단 x ≈ 37–46, 우단 x ≈ 217–226이다.

처리 항목:

1. y좌표 상단 영역(페이지 번호·러닝 헤더) 제거
2. 권 소개 블록 제거 (권 시작 페이지의 작은 글씨 블록)
3. 편집자 소제목 제거 (들여쓰기 없고 숫자로 시작하지 않는 작은 글씨)
4. 줄바꿈으로 분리된 절 본문 병합
5. `¶` (KJV 문단 표시) 제거
6. 들여쓰기된 숫자 시작 줄에서 절 분할

### 7.3 단일 장 책과 러닝 헤더의 불규칙성

- 오바댜·빌레몬서 등 **단일 장 책은 러닝 헤더에 장 번호가 없다** (그냥 "오바댜").
- 권이 시작하는 페이지에는 러닝 헤더가 아예 없고 대신 권 제목과 소개 블록이 온다.
- 페이지 번호와 책 이름의 **좌우 배치가 홀/짝 페이지마다 뒤바뀐다.**

러닝 헤더는 권의 짧은 이름(예: "히브리서")을 얻는 용도로만 쓰고,
장·절 구조 판단에는 쓰지 않는다.

### 7.4 권 이름 대응은 표를 만들지 않는다

한글 권 이름 66개와 영어 권 이름을 손으로 대응시키지 않는다. **두 자료 모두
동일한 정경 순서를 따르므로, n번째로 파싱된 권 = `kjv_en.json`의 n번째 권이다.**
한글 이름은 러닝 헤더에서 얻고, 영어 이름은 순서로 맞춘다.

### 7.5 본문 범위

문서는 1648페이지지만 성경 본문은 요한계시록에서 끝나고 그 뒤는 부록과
MEMO 페이지다. 66권을 채우면 파싱을 종료한다.

헤더의 장 번호도 신뢰하지 않는다. 실측 결과 실제 본문보다 한 장씩 앞서 있다:

- 페이지 24: 헤더 "창세기 6" / 내용은 창세기 5:9–26 (에노스·게난 계보)
- 페이지 30: 헤더 "창세기 12" / 내용은 창세기 11:8–21 (바벨탑·셈의 계보)
- 페이지 1500: 헤더 "디모데전서 6" / 내용은 디모데전서 5장 (과부·장로 규정)

따라서 **장 구분은 절 번호가 1로 리셋되는 지점으로 판단**한다.

### 7.6 검증: 영어 KJV를 스키마 검증기로 사용

킹제임스 흠정역은 KJV와 동일한 본문(Textus Receptus) 계열이므로 권·장·절 구조가
정확히 일치한다. 따라서 별도의 절 수 표를 손으로 만들 필요 없이,
**어차피 다운로드하는 `kjv_en.json`의 구조와 대조**하면 된다.

사용할 영어 KJV 파일은 검증을 마쳤다 (scrollmapper/bible_databases, 퍼블릭 도메인):
**66권, 총 31,102절, 창세기 1533절** — 널리 알려진 KJV 수치와 정확히 일치한다.

`parse_bible.py`는 다음을 만족해야 하며, 실패 시 예외를 던지고 중단한다:

- 권 수가 일치한다 (66권)
- 각 권의 장 수가 일치한다
- 각 장의 절 수가 일치한다
- 어느 절도 빈 문자열이 아니다

이것이 이 프로젝트의 유일한 자동 검증이며, 별도 테스트 프레임워크 없이
`parse_bible.py` 안의 assert로 구현한다. 한 절이라도 누락·병합·중복되면
즉시 드러난다.

잘못 파싱된 구절은 조용히 통과하면 그대로 영상이 되어 공개된다. 이 검증은
생략할 수 없다.

## 8. 렌더링 설계

### 8.1 TTS

edge-tts를 사용한다. 무료이고 API 키가 필요 없다.

- 한국어 해설: `ko-KR-InJoonNeural`
- 영어 구절: `en-GB-RyanNeural` (KJV는 17세기 영국 영어이므로 영국 발음이 어울린다)

문장별로 개별 mp3를 생성한 뒤, 각 파일의 실제 재생 길이를 읽어 자막 타이밍을 정한다.

### 8.2 자막

FFmpeg `drawtext` 필터는 한글 자동 줄바꿈을 지원하지 않아 긴 문장 처리가 번거롭다.
대신 **ASS 자막 파일을 생성해 `subtitles` 필터로 입힌다.** 줄바꿈·정렬·외곽선을
자막 파일 쪽에서 제어할 수 있어 안정적이다.

### 8.3 영상 구성 순서

한 영상은 다음 순서로 진행한다. `build.py`는 이 순서를 고정으로 구현한다.

| 구간 | 화면 | 소리 |
|---|---|---|
| 1. 구절 제시 | 구절 본문(한글) + 출처 표기를 크게 | 무음 (읽을 시간 확보) |
| 2. 영어 낭독 | 영어 구절 자막 | `verse_en` TTS (영국 발음) |
| 3. 한글 낭독 | 한글 구절 자막 | `verse_ko` TTS |
| 4. 묵상 해설 | `narration` 문장별 자막 | `narration` TTS (문장 단위) |

1번 구간이 첫 프레임이므로 쇼츠 피드에서 썸네일 역할을 한다. 길이는 2초로
고정하되, `build.py` 상단 상수로 두어 조정 가능하게 한다.

전체 길이는 `narration` 문장 수로 조절된다. 3–5문장이면 대략 1–2분이 나온다.

### 8.4 영상 합성

- 배경: `bg/`의 이미지 한 장에 FFmpeg `zoompan` 필터로 완만한 Ken Burns 효과
- 해상도: 1080×1920 (9:16)
- 오디오: 문장별 mp3를 순서대로 concat
- 첫 프레임에 구절 본문이 크게 보이도록 구성한다 (쇼츠 피드에서 썸네일 역할)

배경 이미지는 미리 몇 장 받아두고 주제별로 매핑한다. 매 실행 시 이미지를
새로 다운로드하지 않는다.

## 9. 업로드 설계

YouTube Data API v3를 사용한다.

- OAuth 인증은 최초 1회 브라우저로 수행하고 토큰을 로컬에 저장해 재사용한다.
- 예약 게시: `status.privacyStatus = "private"` + `status.publishAt`에 게시 시각 지정
- `upload.py`는 사용자가 명시적으로 실행할 때만 동작한다. 자동 호출 경로를 두지 않는다.

## 10. 오류 처리 방침

| 상황 | 처리 |
|---|---|
| 파서 검증 실패 | 예외 발생 후 중단. `kjv_ko.json`을 쓰지 않는다. |
| 대본 JSON 필드 누락 | `build.py`가 즉시 실패. 부분 렌더링하지 않는다. |
| TTS 호출 실패 | 해당 대본 하나만 실패시키고 나머지 배치는 계속 진행 |
| FFmpeg 실패 | stderr 그대로 노출. 임시 파일은 남겨 원인 추적을 돕는다. |
| 업로드 실패 | MP4는 `out/`에 그대로 둔다. 재실행하면 다시 시도된다. |

## 11. 저작권 관련 메모

- 영어 KJV는 퍼블릭 도메인이다.
- 한글 흠정역('그리스도예수안에' 출판사)은 저작권이 유효하다. 기술적 제약은
  아니지만, 자동 대량 인용 영상을 지속 게시하기 전에 출판사에 사용 허락을
  문의해 두는 편이 채널 운영상 안전하다.

## 12. 명시적 비목표

다음은 이번 범위에 넣지 않는다.

- 주제 태깅 시스템 (grep으로 대체)
- 썸네일 생성기 (쇼츠에 불필요)
- 스케줄러 자동 실행 (주 2–3개 규모에 과함)
- 승인용 웹 UI (영상 파일 직접 확인으로 충분)
- 단계별 큐 폴더 체계 (`inbox/ → approved/ → uploaded/`)
- 성경 통독 시리즈, 주제별 성경 공부 등 다른 채널 포맷
  (쇼츠 파이프라인이 안정된 뒤 별도 설계로 다룬다)
